# Growth Log — 2026-10-19

## Execute sandbox only sees the Code Mode catalog, not top-level tools

### Context
- Necesitaba correr 5 comandos de git en paralelo desde `execute` para revisar ramas, remotos, estado y config.
- Escribí `tools.shell(...)` y las cinco llamadas fallaron con `Unknown tool 'shell'`.

### Root Cause / Core Insight
- `execute` no es un superconjunto del harness: solo expone los tools del catálogo de Code Mode (aquí `graphify`, `opencode`, `rea`) más los que devuelve `search`. `shell` es una herramienta de primer nivel del harness y queda fuera del sandbox aunque aparezca en mi lista de tools.

### The Pattern (transferable)
- Antes de usar `execute` para paralelizar, verificar que cada tool esté en el catálogo de Code Mode o resolverlo con `search(...)`; para todo lo demás, llamar el tool directamente.
- Señal para reconocerlo: un error `Unknown tool '<nombre>'` que sin embargo aparece listado en mis herramientas — es un tool de harness, no de sandbox.

## Installing a git-backed OpenCode plugin on Windows needs the npm fallback

### Context
- Instalé el plugin Superpowers en OpenCode con la config `"plugin": ["superpowers@git+https://..."]`, siguiendo el INSTALL.md.
- En vez de probar suerte con el resolvedor de plugins, apliqué directamente el fallback que el propio INSTALL.md documenta para Windows.

### Root Cause / Core Insight
- Algunos builds de OpenCode en Windows no resuelven specs de plugin con `git+https` (rutas de caché y `git.exe` que Bun no encuentra aunque el terminal sí). El camino fiable es instalar el paquete con el npm del sistema en `~/.config/opencode` y apuntar la config a la ruta absoluta.

### The Pattern (transferable)
- Al instalar un plugin git-backed en OpenCode sobre Windows, saltar directo a: `npm install <spec> --prefix "$HOME\.config\opencode"` y luego poner la ruta absoluta del paquete en `opencode.json`.
- Señal para reconocerlo: la documentación marca un fallback específico de Windows para plugins `git+https`, o la instalación por el gestor de plugins no aparece en los logs.
- Recordar: OpenCode no expande `~`; una entrada `~/...` se trata como nombre de paquete, no como ruta local.
